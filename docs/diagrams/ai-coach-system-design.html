AI Coach — Bucketed Plan Templating

How fitNXT inverts the chatbot paradigm: the AI asks the questions during onboarding, similar users share AI-authored plan templates, and AI usage trends toward zero as the bucket space fills in. Full decision record: docs/ADR-007-ai-coach-plan-templating.md

PRINCIPLE  →  AI AUTHORS (rare, offline)  ·  SYSTEM SERVES (frequent, zero-AI, online)
Zone 1

Adaptive Onboarding

  • User signs up → branching question tree
  • Tree walk is deterministic — zero AI calls
  • Collects: goal, experience, environment, sport, days/week, session length, lifestyle
onboarding_question_nodes (versioned)
Zone 2

Sport Normalization

  • Free-text sport → pg_trgm fuzzy match
  • Match found → resolved sport + alias cached
  • No match → new sport, status = pending_review
sports · sport_aliases (GIN trgm index)
Zone 3 · AI Zone

Bucket Resolution

  • Compose deterministic bucket_key
  • Redis cache hit (24h) → instant resolve
  • Cache miss, bucket exists → DB lookup
  • Bucket missing → Claude generates template (NX lock guards stampede)
plan_template_buckets · ai_fallback_events (cost log)
Zone 4

Clone & Deliver

  • Clone template → new training_plans row
  • One transaction: plan + days + exercises
  • usage_count++ on the source bucket
workouts owns the write · ai-coach owns the decision

AI Coach Chat

  • 5-layer cached context, ~8K tokens/request
  • Session data feeds back into refinement
